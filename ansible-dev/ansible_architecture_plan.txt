# PSTAT Ansible Architecture Plan

## I. The Structural Philosophy
* Pattern: Atomic Roles -> Explicit Playbooks -> Flat Variables.
* The "Surgical" Approach: We do not "adopt" monolithic roles. We extract the specific logic (tasks/templates) from legacy sources and wrap them in new, single-purpose roles.
* The Truth: The Playbook defines *what* is installed; the Host Vars define *how* it is configured.

---

## THE LAYER CAKE ARCHITECTURE
The deployment is structured as a series of sequential layers. Each layer must be stable before the next is applied.

- Layer 1: System Base (The Birth)
  - Goal: Minimum viable OS state.
  - Roles: role_os_updates, role_ntp, role_repos, role_base_tools, role_core_users.
  
- Layer 2: The Shield (The Perimeter)
  - Goal: Secure the network and prevent brute-force.
  - Roles: role_firewall, role_fail2ban.

- Layer 3: Hardening (The Fortress)
  - Goal: Apply high-security benchmarks (CIS/CUI).
  - Execution: Optional/Selective via standalone policy playbook. (Current State: LVM "Alta Model" and CUI Baseline ~84% applied).
  - Note: Operational exceptions made for subscription-manager, usbguard, fapolicyd, and authselect/pam_faillock to preserve stability and Layer 4 compatibility.


- Layer 4: System Apps (The Plumbing)
  - Goal: Integrating the server into the PSTAT management ecosystem.
  - Roles: role_identity (LDAP/SSSD), role_monitoring, role_logging, role_backups, role_nfs, role_guest_agent.

- Layer 5: User Apps (The Payload)
  - Goal: Providing the actual tools for data science and statistics.
  - Roles: role_podman, role_scientific_stack, role_rstudio_server.

## IV. Execution Flow & Workflow
1. Define Host -> inventories/pstat.ini
2. Define Personality -> host_vars/forger2.yml
3. Development Loop: 
   - Use 'test_l1_safe.yml' (The Integration Harness) for rapid iteration using --tags and --limit.
   - Mirror all role changes into the corresponding 'deploy_lX_...' deliverables.
4. Production Deployment:
   - Run 'deploy_l1_base.yml' -> 'deploy_l2_shield.yml' -> (Optional: apply_cis_hardening.yml) -> 'deploy_l4_infra.yml' -> 'deploy_l5_apps.yml'.
5. Run -> ansible-playbook -i inventories/pstat.ini <playbook>.yml --limit <host>
